Enfoques de arquitectura

¿Cómo estructuramos el proyecto Maestro?

A

Monorepo con módulo compartido ⭐ Recomendada

Un solo repositorio con tres módulos Gradle coordinados.

maestro/
├── composeApp/ # UI Web + Android (CMP)
├── server/ # Ktor backend
├── shared/ # Modelos + DTOs compartidos
└── build.gradle.kts
✓ DTOs compartidos cliente-servidor ✓ Un solo PR por feature ✓ Tipado end-to-end en Kotlin
B

Dos repositorios separados

Frontend CMP en un repo, Ktor backend en otro.

maestro-frontend/ # repo 1 (CMP)
maestro-backend/ # repo 2 (Ktor)
✓ Deploys independientes ✗ Modelos duplicados ✗ Dos PRs por feature
C

Frontend delgado + Backend pesado

Toda la lógica vive en Ktor, el CMP solo renderiza lo que recibe.

composeApp/ # Solo UI, sin lógica
server/ # Lógica + datos + estado
✓ Frontend simple ✗ Sin offline ✗ Latencia en cada acción
