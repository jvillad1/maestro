Diseño — API REST

Sección 3 de 4: Endpoints del backend Ktor

Autenticación

POST /api/auth/register   → { token, user }
POST /api/auth/login      → { token, user }

Todos los endpoints siguientes requieren Authorization: Bearer <token>

Estudiantes

GET  /api/students             → List<Student>
POST /api/students             → Student
GET  /api/students/{id}        → Student
PUT  /api/students/{id}        → Student
DEL  /api/students/{id}        → 204

Clases

GET  /api/classes              → List<ClassEntry>
GET  /api/classes?month=2026-05 → List<ClassEntry> (filtrado)
POST /api/classes              → ClassEntry
PUT  /api/classes/{id}         → ClassEntry (toggle paid)
DEL  /api/classes/{id}         → 204

Tareas

GET  /api/tasks          → List<Task>
POST /api/tasks          → Task
PUT  /api/tasks/{id}     → Task
DEL  /api/tasks/{id}     → 204

Eventos

GET  /api/events        → List<Event>
POST /api/events        → Event
PUT  /api/events/{id}   → Event
DEL  /api/events/{id}   → 204
Seguridad

Cada endpoint valida que el recurso solicitado pertenezca al userId del token. Un profe nunca puede leer ni modificar datos de otro.
